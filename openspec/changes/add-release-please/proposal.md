# Proposal

Status: done
Issue: diblaze/bokio-mcp#15

## Why
Every release today is three hand steps that drift (version bumped to 0.4.0 on `main` but never published, a hand-written `## 0.4.0 — unreleased` block, no GitHub Release for `v0.3.0`). Commits are already Conventional Commits, so the version and changelog can be derived from them; the owner keeps the final say on what goes live.

## What Changes
- On every push to `main`, a release pull request is opened or updated that proposes the next version from the commits since the last release (`feat` → minor, `fix` → patch, breaking → minor while below 1.0.0) and writes the changelog entry, `package.json` version and release manifest.
- Merging the release pull request creates the git tag `v<version>` (same shape as the existing `v0.3.0`) and a GitHub Release carrying the changelog entry.
- A created release builds the package and submits it to npm as a *staged* version using the workflow's OIDC identity; nothing is installable until the owner approves it on npm with 2FA. No npm token is stored.
- `package.json` on `main` always equals the latest released version (reset from 0.4.0 to 0.3.0 now); the hand-written `## 0.4.0 — unreleased` changelog block is removed and regenerated by the release pull request.
- Docs: AGENTS.md publishing paragraph and Key Files, CONTRIBUTING.md "Releases", CHANGELOG.md header note.

## Capabilities
### New Capabilities
- `release-automation`: how merged commits on the default branch become a release pull request, a tagged GitHub Release and a staged npm version awaiting maintainer approval.
### Modified Capabilities
- none

## Impact
- New files: `.github/workflows/release-please.yml`, `release-please-config.json`, `.release-please-manifest.json`.
- Edited: `package.json` (`version` 0.4.0 → 0.3.0), `CHANGELOG.md` (header note, unreleased block removed), `AGENTS.md`, `CONTRIBUTING.md`.
- Actions used: `googleapis/release-please-action@v5`, `actions/checkout@v4`, `pnpm/action-setup@v4`, `actions/setup-node@v4` (Node 24 so the bundled npm ≥ 11.15 has `npm stage`).
- Permissions: release job `contents: write`, `pull-requests: write`, `issues: write`; publish job `contents: read`, `id-token: write`.
- Owner steps outside the repo (not tasks): see design.md "Owner steps" — PAT secret `RELEASE_PLEASE_TOKEN`, npm trusted publisher created right before the first release merge (2-day expiry), disallow tokens after the first publish, approve each staged version.
- No runtime dependency, no tarball change (`files` is `dist`, `README.md`), no change to required status checks.
